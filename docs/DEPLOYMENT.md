# Deploy RentEase: Render backend + Vercel frontend

Repository: https://github.com/Aashrithkumar/RentEase

Both services use this repository and its root package-lock.json. Database, JWT, SMTP and Cloudinary secrets belong on Render only. Local .env files and demo passwords are excluded from Git.

## 1. Upload the project

If the upload has not already been completed, run these from the RentEase1 project root:

```powershell
git init
git add .
git commit -m "Prepare RentEase for Render and Vercel"
git branch -M main
git remote add origin https://github.com/Aashrithkumar/RentEase.git
git push -u origin main
```

Skip remote add if origin already exists. Do not force-push or commit .env.

## 2. Create the Vercel project to obtain its domain

Choose **Add New → Project**, import **Aashrithkumar/RentEase**, and select root directory **frontend**. Enable **Include source files outside of the Root Directory in the Build Step** so the shared npm workspace lockfile is available. Choose **Other** as the framework; frontend/vercel.json supplies the commands.

| Setting | Value |
| --- | --- |
| Root Directory | `frontend` |
| Framework Preset | `Other` |
| Install Command | `npm ci --include=dev` |
| Build Command | `npm run build:vercel` |
| Output Directory | Leave override disabled; the build emits `.vercel/output` |
| Node.js Version | `22.x` |

An initial build without RENDER_API_URL intentionally fails with an explanatory message. You can obtain the assigned production domain from project settings before the backend exists. Copy the exact domain; do not assume rentease.vercel.app is available.

## 3. Deploy the backend on Render

Choose **New → Blueprint**, connect the repository, and select render.yaml. It defines a free Node web service named rentease-api, automatically generates strong JWT/scheduler secrets, and asks for private values.

Alternatively, create **New → Web Service** with these settings:

| Setting | Value |
| --- | --- |
| Repository | `Aashrithkumar/RentEase` |
| Branch | `main` |
| Root Directory | Leave blank (repository root) |
| Runtime | Node |
| Build Command | `npm ci --include=dev && npm run build -w backend` |
| Start Command | `npm run start -w backend` |
| Health Check Path | `/api/health` |
| Instance Type | Free for an initial demo |

Set these Render environment variables:

| Key | Value |
| --- | --- |
| NODE_ENV | `production` |
| NODE_VERSION | `22` |
| MONGO_URI | Your Atlas connection string, copied privately from backend/.env or a production database |
| FRONTEND_URL | Exact Vercel production HTTPS origin, with no trailing slash |
| JWT_SECRET | Generated by Blueprint; otherwise a new random secret of at least 32 characters |
| SCHEDULER_SECRET | Generated by Blueprint; otherwise a new random secret |
| CLOUDINARY_CLOUD_NAME | Your configured cloud name |
| CLOUDINARY_API_KEY | Your private configured key |
| CLOUDINARY_API_SECRET | Your private configured secret |
| EMAIL_MODE | `disabled` until email delivery is configured |

Render supplies PORT; the server listens on that port at 0.0.0.0. Do not copy the local weak your_secret_key JWT secret into production. CLOUDINARY_URL is unnecessary when the three Cloudinary values above are set.

Atlas must allow Render's outbound addresses. Find them in the service's **Connect → Outbound** section and add the listed ranges under Atlas **Network Access**. The app requires replica-set transactions. Avoid copying the local MONGO_DNS_SERVERS workaround unless Render actually has DNS errors. The current database contains development demo records; use a separate database for a real launch or retain the clearly labelled demo data for a public demonstration.

Open https://YOUR-ACTUAL-RENDER-HOST/api/health after deployment. A healthy response has HTTP 200 and database: connected. A 503 means MongoDB is unavailable; check Render logs, Atlas network access and credentials.

## 4. Connect and deploy the frontend

In Vercel **Settings → Environment Variables**, add:

| Key | Value | Scope |
| --- | --- | --- |
| RENDER_API_URL | Actual backend HTTPS origin, e.g. `https://your-service.onrender.com` (no /api/v1) | Production |
| VITE_API_URL | `/api/v1` (or leave unset) | Production |

Redeploy Vercel. The build generates Vercel Build Output API routing: /api/* forwards to Render, static files are served directly, and React page routes such as /admin load index.html. Missing asset files stay 404. API responses bypass CDN caching.

The browser calls /api/v1 on its own frontend domain. HttpOnly refresh cookies remain host-only and return through the proxy, avoiding dependence on third-party cookies between vercel.app and onrender.com. Render validates Origin against FRONTEND_URL. Database and Cloudinary credentials must never be VITE_ variables.

If the frontend domain changes, update FRONTEND_URL on Render. If the backend domain changes, update RENDER_API_URL and redeploy Vercel. Preview domains are intentionally not allowed against production; use a separate backend/database for previews.

## 5. Verify the public deployment

1. Load the home page and search properties.
2. Register or sign in; both must redirect to the home page.
3. Reload and confirm the session survives, then sign out.
4. Open /admin directly and reload it as an administrator.
5. Confirm owner property creation/photos and authorized private PDF downloads work.
6. Open /api/health through the frontend domain and confirm database connectivity.

Free Render services sleep after 15 minutes without inbound traffic and can take about a minute to wake. Free services also block outbound SMTP ports 25, 465 and 587, so email starts disabled. Password-reset email requires a working provider and suitable hosting plan or provider integration; in-app notifications still work.

## Email, reminders and administrator setup

On hosting that supports SMTP, set EMAIL_MODE=smtp, SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS and a verified MAIL_FROM. Verify delivery before relying on password reset. Production email is never written to a local file.

For daily reminders, configure an external scheduler to POST to the backend's /api/v1/scheduler/reminders with Authorization: Bearer YOUR_SCHEDULER_SECRET. If moreExpired=true, repeat until false. Do not expose this secret in frontend code. Cron hosting can have separate charges; this Blueprint does not provision it.

To bootstrap a non-demo administrator, temporarily set ADMIN_NAME, ADMIN_EMAIL and ADMIN_PASSWORD (at least 12 characters) against the intended database and run npm run create-admin -w backend. The script creates a new administrator and refuses to change existing accounts. Remove the bootstrap password afterward. You can run it locally with the intended database configuration if Render shell access is unavailable.

## Local verification

```powershell
npm test
npm run build
$env:RENDER_API_URL = 'https://your-service.onrender.com'
npm run build:vercel -w frontend
Remove-Item Env:RENDER_API_URL
```

The last build produces ignored frontend/.vercel/output/config.json and static files. This validates packaging; actual HTTPS login, uploads and email need verification after publishing.
